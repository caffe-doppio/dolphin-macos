# Changelog

Changes made by this fork on top of upstream Dolphin. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

Open work is kept in `TODO` comments next to the entry it belongs to.

## [Unreleased]

### Added

- 2026-10-31. The folder colour menu and Finder agree. It offers Finder's colours in Finder's order, drawn in the tag colours: red, orange, yellow, green and blue as buttons, violet and grey in the submenu. Each is set as the Finder colour tag instead of a `.directory` icon, and Default removes the colour tags. Tags with other names stay. The menu shows the colour of the folder's most recent colour tag as checked. Cyan and brown, which Finder does not have, are left out on macOS.

- 2026-10-31. Folder icons take the colour Finder gives them: the system folder colour, which follows the accent colour and the icon tint, or the colour of the folder's most recent Finder tag. Breeze icons keep their shape; only `.ColorScheme-Accent` changes ([#7](https://github.com/caffe-doppio/dolphin-macos/pull/7)).

### Fixed

- 2026-11-01. The Interface page of Configure Dolphin has its icon again: Dolphin's own, in the system accent colour, as Plasma shows it in its accent colour. The Breeze theme on macOS has no `org.kde.dolphin` icon and Qt does not look in `share/icons`, so the SVG is bundled in a macOS-only resource and drawn by `KIconEngine`, which colours its `.ColorScheme-Highlight` parts. Selected, the folder is black and the dolphin grey, as Plasma draws it on a light accent.
- 2026-11-01. The Trash page of Configure Dolphin shows its macOS note as text instead of `<para>` markup.
  <!-- TODO: Report to kio-extras (26.08.2): kcm_trash's macOS labels hold KUIT markup that is never converted, so QLabel shows it as is. Then drop the conversion in TrashSettingsPage. -->
- 2026-11-01. Alternate rows in the views and the Folders panel use the colour scheme's dark grey instead of a light grey that hid their text. The scheme is now applied before any window exists: Dolphin's item views copy their viewport's palette once, when they enter their scene, and during the main window's constructor that palette was still the macOS one, whose alternate row colour Qt makes opaque.
  <!-- TODO: Report to Dolphin that KItemListView::itemChange() copies the view's palette once and never follows its later changes: switching the colour scheme at run time can leave the same stale rows. -->
- 2026-11-01. The line on the active tab, check boxes, radio buttons and selections use the macOS accent colour instead of Breeze's blue. The Breeze colour scheme sets the palette's highlight to its own blue, so it is replaced with the system accent colour after each palette change, next to the folder colour.

- 2026-11-01. In the Properties dialog, "Open with" names the application macOS opens the file with, instead of "No associated application", and "Change…" picks a new default from the applications LaunchServices offers, or any other, instead of failing to find `keditfiletype` (`dolphinmacopenwith.mm`). KIO reads freedesktop `.desktop` files, which macOS lacks. As in Finder, the row is hidden for a folder, and "Change…" for several items, a remote file or a type macOS does not know.

- 2026-10-31. The Places panel shows folders in the system folder colour, like the views. KFilePlacesView draws its icons with the view's palette, so the colour is set as the application's accent colour.
- 2026-10-31. Choosing a folder icon or colour from the context menu updates the folder at once. The action told the folder listers through KDirNotify, over D-Bus, which macOS does not have; without a session bus it now marks the folder dirty in KDirWatch ([#5](https://github.com/caffe-doppio/dolphin-macos/pull/5)).
- 2026-10-31. Dolphin loads its own plugins (folder colour and other file item actions, settings pages) instead of the ones upstream Dolphin installs in `~/CraftRoot/plugins`. They are installed in `dolphin.app/Contents/PlugIns`, which `main.cpp` puts first in Qt's library paths ([#6](https://github.com/caffe-doppio/dolphin-macos/pull/6)).
  <!-- TODO: A run from build/ has no PlugIns directory and still loads Craft's plugins: use QT_PLUGIN_PATH=$PWD/build/bin. -->
- 2026-10-31. An empty "Information" dock no longer covers the toolbar when Dolphin is built without Baloo ([#1](https://github.com/caffe-doppio/dolphin-macos/pull/1)).
- 2026-10-31. Tests no longer hang waiting for a D-Bus session bus, which macOS does not have ([#2](https://github.com/caffe-doppio/dolphin-macos/pull/2)).
- 2026-10-31. `handleUrl()` keeps a folder in the view on macOS instead of handing it to `QDesktopServices`. The cause is upstream commit `f1770cb0d` ([#3](https://github.com/caffe-doppio/dolphin-macos/pull/3)).
- 2026-10-31. Files dropped on the Trash in the Dock go to the trash, as with Move to Trash. The Dock leaves that to the drag source, and Qt does not tell Dolphin it happened, so the drop end is read from Qt's view (`kitemlistmacdrag.mm`) ([#4](https://github.com/caffe-doppio/dolphin-macos/pull/4)).
